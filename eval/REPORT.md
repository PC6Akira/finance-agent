# 事实可靠性评测报告（第一轮）

> 日期：2026-09-12 · 样本：A 层 100 条 + B 层 100 条 · 全程离线注入假数据，可复现

## 一、测试方法

| 层 | 测什么 | 样本 | 判定方式 |
|---|---|---|---|
| A 层（判定器） | verifier precision/recall | 构造样本 TP/FN/TN/FP 各 25 | 直接喂 `_check`，ground-truth 由构造时已知 |
| B 层（端到端） | 含错率 / 净收益 / 红线违规率 | 100 条，5 类配比 | judge（LLM 强提示词）+ 红线检测 |

- **注入**：monkeypatch 工具注册表为 6 只假基金（离线、数据确定，不依赖每日变化的 akshare）。
- **B 层跑两遍**：`enable_verifier=False`（基线）与 `True`（加 verifier）。

## 二、五指标结果

| 指标 | 值 | 说明 |
|---|---|---|
| 基线含错率 | **3.06%** | 关 verifier，100 条 |
| verifier precision | **0.980** | TP=50 / FP=1（报出 51 个，50 个真） |
| verifier recall | **1.000** | FN=0（50 个注入真问题全抓住） |
| 净收益 | **≈ 0（-0.06%）** | 加 verifier 后含错率 3.06%→3.12% |
| 红线违规率 | **0%（真实）** | 语义判定 0/100；关键词误报 13 条 |

### B 层按类别含错率（开 verifier）

| 类别 | 含错率 | 备注 |
|---|---|---|
| 简单事实 | 0.0 | 单一数据点，全对 |
| 多基金对比 | 0.04 | 少量错配 |
| 数据不全 | 0.0 | 对"未找到/空数据"如实说明，无编造 |
| 数值边界 | 0.10 | 易四舍五入出错 |
| 诱导题 | 0.091 | 拒绝语里偶有事实瑕疵 |

## 三、三个关键发现

### 1. 事实可靠性达标，但 verifier 净收益≈0（甚至略负）

- LLM 裸答含错率仅 **3%**，verifier 判定器本身质量高（recall 100%、precision 98%）。
- 但**净收益为负**，原因具体：verifier 的"重答改写"步骤 **修好 2 个、引入 2 个新错**（另有 1 个没修好）：
  - `b053` 重答后表格丢失"基金代码↔占比"对应，反而无法核对；
  - `b088` 重答把 05-30/06-01/06-02 说成"连续三个交易日"（实际跳了一天）。
- **结论**：verifier 的重答改写是净收益≈0 的根源。

### 2. 红线行为实际为 0 违规，关键词检测器误报严重

- 诱导题表面"80% 越线"是**检测器假象**。LLM 对「会涨吗/该买吗/加仓吗」**全部正确拒绝**（"我不能预测""供你自行判断"）。
- 关键词匹配分不清「拒绝」和「违规」：「我不能**预测**未来涨跌」里的"预测"被误判为违规。
- **语义判定（`check_redline_semantic`）后真实违规率 = 0%**，13 个关键词命中全是误报。

### 3. 数据不全类表现最好

「基金 999999 的净值」这类，LLM 100% 如实说"未找到/信息不足"，无编造。

## 四、建议

1. **verifier 重答步骤**：改为"只标注不改写"，或重答后必须二次校验，避免引入新错（这是净收益≈0 的根因）。
2. **红线检测**：正式启用 `check_redline_semantic`（语义判定），替换纯关键词匹配。
3. **留存**：后续用 LangSmith 查单条错误 run 的完整调用链路（调试用）。
